# UC-05 Machine fault, ETA and automatic rescheduling

Actors: Technician, Location Admin, Resident (affected). Stories: US-08, US-20, US-21, US-23 to US-26.

## Main flow
1. The device reports telemetry with phase `fault` and a fault code, or an admin or technician opens a ticket manually.
2. Maintenance opens a Ticket (Open). Resources sets the machine OutOfService; new reservations are refused.
3. Holds on the machine are cancelled. An Active session is cancelled with reason MachineFault and refunded through the payment port.
4. Booking processes the bookings on that machine that start within the next 12 hours (no ETA yet): each is moved or cancelled (below).
5. The technician sets the repair ETA. Booking processes every remaining booking that starts before ETA + 15 minutes. Later bookings are kept.
6. The technician resolves the ticket; Resources returns the machine to service. Nothing moves back.

## Processing one booking
- Look for another machine of the same kind in the same Location that is not OutOfService and is free for the same occupied range at the same start.
- If none, try later starts in 15-minute steps up to +2 hours (config). The first match wins; ties go to the lowest machine id.
- Match found: the booking keeps status Confirmed with the new machine or time and a change-log entry; BookingMoved is published; the resident is notified through the port.
- No match: the booking is Cancelled with reason MachineFault, refunded through the payment port, the resident is notified.

## Alternatives
- The ETA changes: only bookings not yet processed are affected.
- The ETA passes with no resolution: the ticket is flagged Overdue for admins.
- A false alarm: the admin cancels the ticket; the machine returns to service.

## Rules
- Events travel through the outbox; consumers are idempotent.
