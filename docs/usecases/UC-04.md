# UC-04 Hold a machine

Actor: Resident (member). Story: US-14.

## Main flow
1. The resident chooses a free machine and a hold length of 5, 10 or 15 minutes.
2. The platform checks that the machine is free from now for that length (no reservation overlaps it, not OutOfService, not busy).
3. The platform calls the payment port with the fixed price for that length.
4. A Hold booking is created from now to now + length; the machine shows as Reserved for everyone else.
5. The resident arrives, presses the button on the machine and claims the code (UC-08); the hold becomes the session.
6. If the resident does nothing, the hold expires (status Expired) and the machine is free again.

## Alternatives
- The machine is busy or a booking starts inside the hold window: `machine-unavailable` or `slot-conflict`.
- The resident already has an active hold: `hold-limit`.

## Rules
- Prices are fixed per length and configured per Location.
- A hold does not extend; the resident can create a new hold after the first ends.
- A hold is cancelled automatically if the machine goes OutOfService (UC-05).
