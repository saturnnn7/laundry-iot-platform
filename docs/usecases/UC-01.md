# UC-01 Register, set up or join a location

Actors: Location Admin, Resident, Technician. Stories: US-01 to US-05, US-09, US-30.

## Main flow - admin
1. The admin registers with email, password (min 10 characters) and display name, account type Admin.
2. The admin creates a Location with a name and a time zone.
3. The admin adds programs (name, kind, minutes as a multiple of 15, price) and machines (name, kind, deviceId).
4. The admin sets Location config (booking limits, hold prices, buffers) or keeps the defaults.
5. The admin creates invite codes for Resident or Technician with an expiry and a maximum number of uses.

## Main flow - resident or technician
1. The user registers (account type Resident) and logs in.
2. The user enters an invite code.
3. The platform checks the code (valid, not expired, uses left) and adds the membership with the role of the invite.

## Alternatives
- Email already used: `validation` problem.
- Invalid, expired or used-up invite: `invite-invalid`.
- A technician joins several Locations with several codes.
- Google login (Tier 2) creates or links a local user, then continues as above.

## Rules
- A Location is the tenant boundary: every query is scoped to the Locations the user belongs to.
- deviceId is unique across the platform.
- Passwords are hashed by ASP.NET Core Identity; access tokens are JWT.
