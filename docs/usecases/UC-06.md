# UC-06 Cycle finished

Actor: Device (trigger), Resident (notified). Story: US-19.

## Main flow
1. Telemetry shows phase `finished`.
2. Booking completes the Active session; SessionCompleted is published.
3. The platform notifies the resident through the notification port (a logging stub in the first version).
4. When the door is opened the device returns to phase `idle` and the machine shows as Available again.

## Alternatives
- The resident never opens the door: the machine stays InUse until phase `idle`; admins see it in the overview.
- The device goes offline during the cycle: the session stays Active until telemetry resumes or an admin intervenes.

## Rules
- The cycle state comes only from telemetry; the backend never assumes a cycle ended because the planned time passed.
